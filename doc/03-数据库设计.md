## 3. 关系图

```
api_project 1─n api_env
api_project 1─n api_group 1─n api_url 1─1 api_url_doc
api_project 1─n api_test_record
api_project 1─n flow_info 1─n flow_step
flow_info   1─n flow_run 1─n flow_run_step
api_sync_log n─1 api_project
sys_config  独立 KV
```

## 4. 设计要点

1. **同步幂等**：api_url 以 `(group_id, method_type, request_url)` 唯一键 upsert；分组按 controller_name 匹配。
2. **冗余 project_id** 到 api_url / api_test_record / flow_info：树形导航与统计免多级 join。
3. **快照设计**：flow_run / flow_run_step 保存名称与请求响应快照，保证历史可回溯，不受定义变更影响。
4. **响应体截断**：api_test_record.response_body、flow_run_step.response_body 按 `max-body-log-size` 截断，防止单条记录过大。
5. **软删**：业务主数据用 del_flag；运行记录（run 系）只增不改不删。
