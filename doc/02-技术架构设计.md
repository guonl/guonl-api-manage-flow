> 版本：v2.0 ｜ 基础框架：Spring Boot 4.1.1 / JDK 17 ｜ AI：Spring AI 2.0.1

## 1. 总体架构

```
┌────────────────────────────────────────────────────────────┐
│                     浏览器（Vue3 SPA）                       │
│   Element Plus ｜ 调试台 ｜ 流程编辑器 ｜ AI 助手            │
└──────────────────────────┬─────────────────────────────────┘
                           │ HTTP (REST /api/*)
┌──────────────────────────▼─────────────────────────────────┐
│                api-manage-admin (Boot 4.1.1)                │
│ ┌─────────┐ ┌─────────┐ ┌──────────┐ ┌────────┐ ┌───────┐  │
│ │ 认证     │ │ API 管理 │ │ 调试代理  │ │ 流程引擎│ │ AI 服务│  │
│ └─────────┘ └────┬────┘ └────┬─────┘ └───┬────┘ └───┬───┘  │
│                  │           │RestTemplate│          │      │
│              ┌───▼───────────▼───┐   ┌─────▼──────┐   │      │
│              │  MySQL (HikariCP) │   │ 目标服务/AI │   │      │

        ┌──────────────────┴──────────────────┐

## 2. 模块职责

| 模块 | 职责 |
|---|---|
| api-manage-admin | 管理端：REST API、调试代理、流程引擎、AI 接入、静态资源托管（SPA） |
| api-manage-tools | 嵌入 jar：`@Endpoint(id="api-manage")` 暴露被接入服务全部接口元数据 |

### 2.1 api-manage-admin 内部分层

```
com.guonl
├── common/          # 统一响应、异常、常量、工具（分页、AES、JsonPath）

├── interceptor/     # AuthInterceptor（Session 认证）

### 2.2 api-manage-tools（Boot 4 迁移要点）

| 迁移点 | 旧（Boot 2.7 / javax） | 新（Boot 4.1 / jakarta） |
|---|---|---|
| Servlet API | `javax.servlet.*` | `jakarta.servlet.*` |
| 路径匹配 | `PatternsRequestCondition` | `PathPatternsRequestCondition`（Spring 7） |
| 参数名发现 | `LocalVariableTableParameterNameDiscoverer`（已移除） | 默认 StandardReflectionParameterNameDiscoverer + `-parameters` 编译参数 |
| 自动装配 | `META-INF/spring.factories` | `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports` |
| JSON | fastjson 1.2.62 | Jackson 3（`tools.jackson.*`，Spring Boot 4 默认内置） |

## 3. 技术选型与升级决策

### 3.1 版本矩阵

| 组件 | 版本 | 说明 |
|---|---|---|
| Spring Boot | 4.1.1 | 2026-08 发布线；starter 更名见 3.2 |
| JDK | 17 | Boot 4 最低要求 17 |
| Spring Framework | 7.0.x（Boot 4 传递） | Jakarta EE 11 基线 |
| Spring AI | 2.0.1（BOM 2.0.x） | 官方兼容 Boot 4.0/4.1；OpenAI starter |
| MyBatis Starter | mybatis-spring-boot-starter 4.0.x | 官方矩阵：Boot 4.0+ ↔ Java 17+ |
| MySQL Driver | com.mysql:mysql-connector-j | 新坐标 |
| 连接池 | HikariCP（Boot 默认） | 移除 Druid |
| JSON Path | com.jayway.jsonpath:json-path 2.9.0 | 流程上下文提取 |
| 前端 | Vue 3 + Element Plus + Axios | 本地构建，产物放 static，hash 路由 |

### 3.2 关键升级决策

| # | 决策 | 理由 |
|---|---|---|
| D1 | `spring-boot-starter-web` → `spring-boot-starter-webmvc` | Boot 4 中旧 starter 已废弃 |
| D2 | 移除 Thymeleaf，前端改 Vue3 SPA | 交互复杂度（调试台/流程编辑器）远超模板引擎适合范围；SPA 产物随 jar 分发，零额外部署 |
| D3 | 移除 PageHelper，自实现 `LIMIT offset,size` 分页 | 老版本 1.2.5 与 Boot 4 不兼容，仅两处列表查询，自实现成本更低 |
| D4 | 移除 Druid，改 HikariCP | Boot 4 默认集成，配置最简 |
| D5 | tools 模块 fastjson → Jackson 3 | Boot 4 默认 Jackson 3；tools 不再自带 JSON 依赖 |
| D6 | Session 认证（admin 单账号，密码 BCrypt） | v2.0 简化安全模型，预留 JWT/RBAC 扩展 |
| D7 | RestTemplate 做调试代理与流程执行 | 同步阻塞模型足够；Boot 4 仍可用，无需引入 WebFlux |
| D8 | AI 通过 Spring AI 2.0.1 OpenAI 兼容协议接入 | 支持任意 OpenAI 兼容网关（DeepSeek/Qwen/vLLM 等），运行时可从 sys_config 读取配置动态构建 |

### 3.3 Spring AI 2.0.1 接入设计

AI 不依赖 yml 配置，全部运行期从 `sys_config` 表动态读取（key：`ai.base-url` / `ai.api-key` / `ai.model` / `ai.temperature`），支持任意 OpenAI 兼容网关（DeepSeek/Qwen/vLLM 等），在系统设置页保存后立即生效。

```
AiService.buildClient() 构建链路（Spring AI 2.0.1 + OpenAI 官方 SDK 4.49.0）：

sys_config 读取（ai.base-url / ai.api-key / ai.model / ai.temperature）
  → OpenAIClientImpl（OpenAI 官方 SDK 客户端）
      + ClientOptions.httpClient(SpringAiOpenAiHttpClient.timeout(60s))
      + ClientOptions.baseUrl(...) / apiKey(...)
  → OpenAiChatModel.builder()
      .openAiClient(client)                 # 同步客户端
      .openAiClientAsync(client.async())    # 异步客户端（2.0.x 必须同时设置）
      .options(OpenAiChatOptions.model(...).temperature(...))
  → ChatClient.builder(model).build()
```

- **指纹缓存**：以 `baseUrl | apiKey哈希 | model | temperature` 为指纹缓存 ChatClient；设置保存时调用 `evictClient()` 失效缓存，下次调用懒加载重建。
- **状态语义**：`GET /api/ai/status` 返回 `{configured, ready}`；`configured` = 三项核心配置非空；`ready` = 缓存客户端已构建（懒加载语义，保存配置后重置为 false，首次成功调用后变为 true）。
- 未配置时 AI 场景端点统一返回错误码 4001「AI 未配置」。
- 依赖：`spring-ai-starter-model-openai` + BOM `spring-ai-bom:2.0.x`（Maven Central 可达）。

## 4. 关键流程设计

### 4.1 Actuator 同步流程

```
管理端 ──GET {manageUrl}/api-manage──▶ 目标服务 actuator 端点
   │                                        │
   │ 返回 ApiUrlMappings[]（controller/url/method/参数结构）
   ▼
同步预览（diff）：
  本地按 (requestUrl + methodType) 匹配
  ├── 新增：远端有本地无 → 待插入
  ├── 更新：两边都有 → 比对参数结构，更新 api_url / api_url_doc
  └── 下线：本地有远端无 → 标记 url_status=OFFLINE
用户确认 → 事务落库（按 controllerName upsert api_group）
```

### 4.2 调试代理流程

```
浏览器 POST /api/debug/send
  { projectId, envId, method, url(含{{var}}), headers, params, bodyType, body }
    │ 1. 解析环境 Base URL + 变量替换
    │ 2. RestTemplate 执行（超时可配，记录 start/end）
    │ 3. 捕获 status/headers/body/耗时；异常转为统一错误结构
    │ 4. 异步落 api_test_record（关联接口/环境/用户）
    ▼
返回 { status, costMs, headers, body, size }
```

### 4.3 流程编排引擎

```
FlowEngine.run(flowId, initVars, mode)
  ctx = { initVars }                      # 上下文
  for step in steps (按 sortOrder，仅 enabled):
      if step.delayMs > 0: sleep
      req = render(step)                  # {{var}} → ctx 值
      resp = httpExecute(req)             # 复用调试代理执行器
      extracts: for each {jsonPath → var}: ctx[var] = JsonPath.read(resp.body)
      assertions: for each: pass/fail     # 失败 → step.status=FAILED
      if step 失败 and onFailure=TERMINATE: 终止流程
      逐步落库 flow_run_step（请求/响应/提取/断言快照）
  flow_run.status = SUCCESS / FAILED
```

- **单步重跑**：`POST /api/flow/run/{runId}/step/{runStepId}/rerun`，以该步之前步骤生成的上下文快照为初始上下文，仅执行该步并更新其记录。
- **占位符语法**：`{{var}}`；URL / Header / Query / Body 均支持。
- **出参提取**：`extractRules: [{"varName":"token","jsonPath":"$.data.token"}]`，提取结果写入流程上下文，后续步骤以 `{{token}}` 引用。
- **断言类型**（target 为响应体 JsonPath，如 `$.data.status`；STATUS 类型的 expect 表示期望 HTTP 状态码）：
  EQUALS / NOT_EQUALS / CONTAINS / NOT_CONTAINS / NOT_NULL / GT / LT / GTE / LTE / STATUS。
  JSON 结构：`[{"type":"EQUALS","target":"$.code","expect":"0","desc":"业务码校验"}]`。
- **失败策略与运行模式**：步骤 onFailure = TERMINATE / CONTINUE；运行 mode = DEBUG（任一步失败立即终止）/ NORMAL（按各步 onFailure 决定是否继续）。DELAY 步骤（stepType=DELAY + delayMs）用于步骤间延时。
- **变量优先级**：所选环境的 `baseUrl` 等同名变量优先于运行时传入的 initVars。

### 4.4 AI 服务流程

```
前端 ──POST /api/ai/{scene}──▶ AiService
        1. 读 sys_config（ai.base-url / ai.api-key / ai.model / ai.temperature）
           → 三项核心配置非空才 configured；未配置返回 4001
        2. 按配置指纹取缓存 ChatClient（无缓存则懒加载构建，见 3.3）
        3. 场景 Prompt 模板：
           - chat：自由对话（内置默认人设 system prompt）
           - analyze：注入 请求/响应 JSON，分析调用结果与问题定位
           - genData：注入 requestParamMap，生成接口测试数据
           - genDoc：注入 接口元数据+参数结构，生成接口文档
           - genFlow：注入 项目API清单 + 流程步骤Schema，生成流程编排 JSON
        4. 同步返回（v2.0 不做流式，预留）
```

辅助端点：
- `GET /api/ai/status` → `{configured, ready}`，前端据此控制 AI 功能入口的可用态。
- `POST /api/ai/test` → 连通性测试，固定 prompt「请只回复两个字：pong」，返回 `{success, reply, latencyMs}`。

### 4.5 REST 端点总览

统一前缀 `/api`（除 `/auth/login` 外均需登录态），统一响应 `ApiResult{code,msg,data,success}`。

| 控制器 | 端点 | 说明 |
|---|---|---|
| AuthController | POST /auth/login、/auth/logout；GET /auth/me；PUT /auth/password | 登录认证 |
| ProjectController | GET /project/page、/list、/{projectId}；POST、PUT、DELETE /{projectId} | 项目管理 |
| EnvController | GET /env/list；POST、PUT、DELETE /{envId} | 环境管理 |
| GroupController | GET /group/list、/{groupId}；POST、PUT、DELETE /{groupId} | 接口分组（按 Controller 维度） |
| ApiUrlController | GET /api/tree、/search、/{urlId}；POST、PUT、PUT /{urlId}/status、/{urlId}/doc；DELETE /{urlId} | 接口管理（树形含分组） |
| SyncController | POST /sync/{projectId}；GET /sync/log | Actuator 接口同步 |
| DebugController | POST /debug/send；GET /debug/template、/debug/records、/debug/records/recent、/debug/record/{recordId} | 调试代理与历史 |
| FlowController | GET /flow/list、/{flowId}、/run/list、/run/{runId}；POST、PUT、DELETE /{flowId}；POST /import、/{flowId}/export、/run、/run/{runId}/step/{runStepId}/rerun | 流程编排与运行 |
| AiController | GET /ai/status；POST /ai/test、/chat、/analyze、/gen-data、/gen-doc、/gen-flow | AI 服务（7 端点） |
| SysController | GET /sys/config、/sys/dashboard；POST /sys/config、/sys/password | 系统设置与工作台统计 |

工作台 `GET /api/sys/dashboard` 返回：`projectCount / apiCount / flowCount / todayDebugCount / todayFailCount / recentDebugs / recentRuns`。

## 6. 错误码与安全

| 错误码 | 含义 |
|---|---|
| 0 | 成功 |
| 400 | 参数错误 |
| 401 | 未登录 |
| 404 | 资源不存在 |
| 500 | 服务端异常 |
| 4001 | AI 未配置 |
| 4101 | 目标服务调用失败（调试代理/流程步骤） |

安全措施：登录密码 BCrypt 落库；敏感配置防泄露——`GET /api/sys/config` 回显时对敏感项脱敏（ai.api-key 前 6 位 + `****` + 后 4 位，password 固定 `******`）；`POST /api/sys/config` 保存时脱敏值/空串/password 恒跳过不覆盖（`SENSITIVE_KEYS = {ai.api-key, password}`），密码修改仅走 `POST /api/sys/password`（校验原密码 + 新密码 ≥6 位），配置保存后自动 `evictClient()` 使 AI 客户端缓存失效；调试代理 URL 仅允许 http/https（v2.0 信任内网，仅做协议校验）；统一异常处理器兜底。
