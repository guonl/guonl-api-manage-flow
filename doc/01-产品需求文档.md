# APIFlow 产品需求文档（PRD）

> 项目代号：APIFlow（原 api-manage）
> 版本：v2.0
> 日期：2026-10-07

---

## 1. 产品定位

APIFlow 是一套面向研发团队的 **API 全生命周期管理与流程编排平台**，核心解决三类痛点：

1. **API 资产散落**：团队接口文档分散、版本不一致、无法快速检索。APIFlow 通过 actuator 自动采集 + 手工维护，形成统一的 API 资产库。
2. **接口调试低效**：传统工具（Postman/Swagger UI）与环境切换、参数拼装割裂。APIFlow 提供类 Postman 的在线调试体验，且直连企业内网环境（浏览器同源代理，无跨域）。
3. **接口串联手工化**：调用方接口依赖上游接口产出（如先登录拿 token 再调业务接口），日常验证全靠复制粘贴。APIFlow 提供可视化流程编排：步骤化调用、上下文传参、断言校验、一键回放。

## 2. 目标用户与角色

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| 后端研发 | 被测服务开发者 | 快速查看/搜索本服务全部接口、调试接口、排查调用链 |
| 测试工程师 | 接口测试人员 | 批量管理第三方接口、调试、编排回归流程并回放 |
| 前端/联调人员 | 消费接口的人 | 查看接口文档、快速试调、理解上下游参数衔接 |

v2.0 采用简化单角色（管理员）+ 登录认证，账号密码存于 `sys_config`，预留多角色扩展。

## 3. 功能模块总览

```
APIFlow
├── 1. 工作台 Dashboard        —— 数据概览、快捷入口、最近操作
├── 2. 项目管理                —— 应用/项目档案、环境管理、actuator 接口同步
├── 3. API 管理                —— 项目→分组→接口三级树、接口详情、文档维护
├── 4. 接口调试（Postman）     —— 请求构建、代理发送、响应查看、调试历史
├── 5. 流程编排                —— 线性步骤编排、上下文传参、断言、调试与回放
├── 6. AI 助手                 —— 模型对话、结果分析、编排生成、文档生成
└── 7. 系统设置                —— AI 模型配置、登录账号
```

## 4. 详细功能需求

### 4.1 登录与认证

- FR-AUTH-01：登录页输入账号密码，校验通过后写入 Session，有效期由容器管理。
- FR-AUTH-02：除 `/api/auth/*`、静态资源外，全部 REST 接口需登录访问，未登录返回 401 JSON（前端统一跳转登录页）。
- FR-AUTH-03：默认账号 admin / admin123，密码存 `sys_config`（可修改）。
- FR-AUTH-04：登出销毁 Session。

### 4.2 项目管理

- FR-PRJ-01：项目列表（分页、按名称/状态搜索），字段：项目名、描述、所属系统、负责人、状态（启用/停用）。
- FR-PRJ-02：新建/编辑/删除（软删）项目。
- FR-PRJ-03：**环境管理**：每个项目可配置多个环境（如 dev/test/pre/prod），字段：环境名、Base URL、描述；调试与流程运行时按环境拼接请求地址。
- FR-PRJ-04：**Actuator 同步**：项目绑定「管理地址」（部署了 api-manage-tools 的服务 actuator 根地址，如 `http://host:port/actuator`），点击同步：
  - 拉取 `api-manage` 端点全量接口清单；
  - 进入**同步预览**：展示新增接口、更新接口（URL+Method 匹配）、失效接口（本地有、远端无）三类 diff；
  - 用户确认后落库：按 controller 归入分组（`api_group`），接口写 `api_url`，文档数据（请求参数说明、响应示例）写 `api_url_doc`；
  - 失效接口默认标记「已下线」（`url_status=OFFLINE`），可选择物理删除。
- FR-PRJ-05：同步历史记录（每次同步时间、新增/更新/下线数量）。
- FR-PRJ-06：**手工采集**：对未接入 tools 的第三方服务，支持手工新增接口，归属到指定项目/分组。

### 4.3 API 管理

- FR-API-01：三级树形导航（项目 → 分组 → 接口），支持关键字过滤接口。
- FR-API-02：接口列表展示：方法名、请求 URL、HTTP 方法、Content-Type、状态、标签。
- FR-API-03：接口详情：
  - 基本信息：URL、方法、Content-Type、描述、标签；
  - 请求参数：`requestParamMap`（参数名/类型/说明）结构化展示与编辑；
  - 响应结构：`returnParamMap` 结构化展示与编辑；
  - 文档增强（`api_url_doc`）：请求头说明、Query 参数说明、成功/失败响应示例（JSON）。
- FR-API-04：接口可复制调试地址、一键跳转调试页。
- FR-API-05：分组管理：手工新增分组（如「第三方接口」）、重命名、删除（仅删空分组）。
- FR-API-06：接口状态：启用 / 停用 / 已下线；标签用于自定义分类（如 核心链路、灰度）。

### 4.4 接口调试（类 Postman）

- FR-DBG-01：调试台支持从 API 树选中接口**带入模板**（URL、Header、Body 按采集的参数自动生成骨架），也可全新手写请求。
- FR-DBG-02：请求构建：
  - Method：GET/POST/PUT/DELETE/PATCH；
  - URL：支持 `{{env}}` 环境前缀 + Query 参数表格/文本双模式；
  - Headers：键值表格（自动补全 Content-Type 等）；
  - Body：none / form-data / x-www-form-urlencoded / raw(JSON、XML、Text)，带格式校验与美化。
- FR-DBG-03：**后端代理发送**：请求由管理端服务端转发（规避浏览器 CORS 与内网限制），服务端记录耗时、状态码、响应头、响应体。
- FR-DBG-04：响应区：状态码/耗时/响应大小徽标；Body 支持 Pretty（JSON 树可折叠）、Raw、预览三视图；响应头列表。
- FR-DBG-05：**变量替换**：请求中 `{{var}}` 占位符从当前项目环境变量解析（v2.0 环境变量即环境的 Base URL，预留键值对扩展）。
- FR-DBG-06：**调试模板**：某接口的最近一次调试参数自动保存为模板，下次打开自动带出。
- FR-DBG-07：**调用历史**：按接口维度记录每次调用（请求/响应摘要、耗时、状态、调用人、时间），支持查看详情、再次发送。
- FR-DBG-08：从调试台一键「存为接口」：将当前请求保存到指定项目/分组。

### 4.5 流程编排

- FR-FLOW-01：流程定义：名称、描述、归属项目、启用状态。
- FR-FLOW-02：**步骤编排（线性）**：流程包含有序步骤，每步绑定一个 API（从 API 树选择或手工填写 URL），支持拖拽排序、启用/禁用单步、复制步骤。
- FR-FLOW-03：每步可配置：
  - 请求覆盖：URL 追加参数、Headers 增量、Body 模板（支持 `{{var}}` 占位符）；
  - **上下文提取**：JSONPath 表达式 → 上下文变量名（如 `$.data.token → token`），多个提取规则并存；
  - **断言**：字段路径 + 匹配方式（等于/包含/正则/非空/JSONPath 存在）+ 期望值；
  - 失败策略：终止流程（默认）/ 继续执行；
  - 延时：执行前等待毫秒数。
- FR-FLOW-04：**占位符解析**：步骤请求模板中 `{{var}}` 从流程上下文取值（前序步骤提取 + 初始变量），未解析到则原样保留并告警。
- FR-FLOW-05：**调试运行**：保存前可试运行，实时查看每步执行结果（请求/响应/提取值/断言结果/耗时），失败步骤可**单步重跑**（复用已生成的上下文）。
- FR-FLOW-06：运行历史：每次运行生成 Run 记录（状态：成功/失败/中止、总耗时、触发方式），并保留全部步骤明细，支持查看与再次执行。
- FR-FLOW-07：流程 JSON 导入/导出（便于团队共享与迁移）。
- FR-FLOW-08：上下文初始变量：运行时可给定初始变量（如固定 token、时间戳）。
- FR-FLOW-09：**AI 生成编排**（联动 AI 助手）：用自然语言描述场景，AI 输出流程 JSON，一键导入。

### 4.6 AI 助手（Spring AI 2.0.1，OpenAI 兼容协议）

- FR-AI-01：**模型配置**：系统设置中配置 Base URL、API Key（AES 加密存储）、模型名称、温度等；提供连通性测试。
- FR-AI-02：**对话助手**：侧边对话窗口，多轮会话（会话历史存内存即可，v2.0 不落库）。
- FR-AI-03：**调用结果分析**：调试页/流程运行页一键将请求与响应发给 AI，输出：接口行为解读、异常原因分析、排查建议。
- FR-AI-04：**测试数据生成**：依据接口的 `requestParamMap` 生成合法/边界 JSON 测试数据。
- FR-AI-05：**流程编排生成**：输入自然语言场景（选择项目后携带项目 API 清单作为上下文），AI 输出符合流程 Schema 的 JSON，可预览并导入流程编辑器。
- FR-AI-06：**接口文档生成**：基于接口采集信息 + 示例，生成 Markdown 使用文档。
- FR-AI-07：AI 调用统一走服务端代理，前端不接触 API Key；未配置模型时相关功能优雅降级（提示先去设置）。

### 4.7 工作台 Dashboard

- FR-DSH-01：统计卡片：项目数、接口总数、今日调用次数、流程数、流程运行成功率。
- FR-DSH-02：快捷入口：新建项目、去调试、新建流程。
- FR-DSH-03：最近记录：最近调试调用 Top10、最近流程运行 Top10。

### 4.8 系统设置

- FR-SYS-01：AI 模型配置（见 FR-AI-01）。
- FR-SYS-02：登录密码修改。
- FR-SYS-03：系统信息展示（版本、JDK、同步端点说明）。

## 5. 非功能需求

| 编号 | 类别 | 要求 |
|---|---|---|
| NFR-01 | 性能 | 接口树/列表加载 < 500ms；调试代理透传增加耗时 < 50ms；流程引擎支持 50 步内流程 |
| NFR-02 | 安全 | API Key AES 加密存储；密码 BCrypt 存储；调试代理仅支持 http/https，禁 file 等协议；拦截器防未授权访问 |
| NFR-03 | 兼容 | 主流 Chrome/Edge；数据库 MySQL 5.7+ / 8.0，utf8mb4 |
| NFR-04 | 可维护 | 后端分层清晰（controller/service/dao）；统一响应/异常处理；关键流程有日志 |
| NFR-05 | 技术栈 | Spring Boot 4.1.1 / JDK 17 / Spring AI 2.0.1 / MyBatis / Vue3 + Element Plus |

## 6. 用户故事（核心场景）

1. **同步接口**：作为后端研发，我把 api-manage-tools 引入新服务并配置管理地址，在管理端点一下「同步」，全部接口带参数说明自动入库，省去手写文档。
2. **快速调试**：作为测试，我在 API 树点开接口 → 调试页自动填充参数模板 → 切换环境 → 发送 → 查看 Pretty 响应，全程不离开浏览器。
3. **流程串联**：作为测试，我编排「登录 → 创建订单 → 查询订单 → 取消订单」，第 2 步从登录响应提取 token，第 3 步从创建订单响应提取 orderId，一键运行全流程，失败步骤单步重跑。
4. **回归回放**：每天用流程运行历史对比接口是否回归正常。
5. **AI 排查**：调试返回 500，一键让 AI 分析响应报错原因，给出排查建议。
6. **AI 编排**：我告诉 AI「先调 /login 拿 token，再调 /order/create 下单并提取订单号」，AI 生成流程 JSON，我导入编辑器微调后使用。

## 7. 边界与约束

- v2.0 流程编排为**线性顺序**执行（if/loop 分支列为 v3 规划）。
- 定时任务、Webhook 触发运行列为 v3 规划。
- OpenAPI/Swagger 文件导入列为 v3 规划（当前以 actuator 同步 + 手工录入为主）。
- 多用户与权限体系（RBAC）列为 v3 规划。

## 8. 验收标准（摘要）

- 引入 tools 的示例服务可被同步，接口与参数说明完整入库，二次同步 diff 正确。
- 调试台可完成 GET/POST（JSON/form）请求，代理转发成功，历史可查。
- 演示流程「A 出参 → B 入参」可编排、可运行、断言生效、历史完整。
- AI 助手在配置 OpenAI 兼容模型后：对话、结果分析、流程 JSON 生成可用；未配置时功能降级有提示。
- 全部页面在未登录时跳转登录页；`mvn clean package` 一次通过。
