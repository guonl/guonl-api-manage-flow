# APIFlow 使用说明

> 面向使用者的操作手册 ｜ 配套文档：[README](../README.md) ｜ [技术架构](02-技术架构设计.md) ｜ [测试报告](07-测试报告.md)

## 1. 系统简介

APIFlow 是一套 **API 收集管理 + 接口调试 + 流程编排 + AI 辅助** 的一体化管理平台：

- **接口收集**：业务服务引入 `api-manage-tools` jar 后，管理端通过 Actuator 端点一键同步全部接口元数据；
- **接口调试**：类 Postman 调试台，支持环境变量、请求历史、AI 生成测试数据 / 分析响应；
- **流程编排**：接口 A 的出参提取后作为接口 B 的入参，串行编排、断言校验、失败策略、单步重跑；
- **AI 助手**：基于 Spring AI 2.0.1（OpenAI 兼容协议），支持 DeepSeek / Qwen / vLLM 等任意兼容网关。

## 2. 快速上手（5 分钟）

1. 建库执行 [doc/sql/api-manage-v2.sql](sql/api-manage-v2.sql)，配置数据源后构建启动（见 README「快速开始」）；
2. 浏览器访问 `http://localhost:8081`，使用初始账号 **admin / admin123** 登录（首次启动自动写入）；
3. **建议立即修改密码**（右上角头像 → 修改密码）；
4. 进入「系统设置」配置 AI（可选，不配置不影响核心功能）；
5. 业务服务接入 tools jar → 管理端「项目」→「同步接口」；
6. 开始调试接口、编排流程。

## 3. 登录与认证

| 项 | 说明 |
|---|---|
| 地址 | `http://<host>:8081/`（未登录自动跳转登录页） |
| 初始账号 | `admin` / `admin123`（首次启动由应用写入，BCrypt 加密落库） |
| 会话 | Session 认证，默认 30 分钟无操作过期 |
| 修改密码 | 系统设置页或右上角入口；需校验原密码，新密码 ≥ 6 位 |

## 4. 工作台

登录后首页为工作台，提供全局概览：

- **统计卡片**：项目数 / 接口数 / 流程数 / 今日调试次数与失败次数，点击卡片直达对应模块；
- **最近调用**：最近 8 条接口调试记录（方法、状态、耗时）；
- **最近运行**：最近 8 条流程运行记录，点击可查看运行详情；
- **快捷入口**：接口调试 / 流程编排 / AI 助手 / 系统设置。

## 5. 项目与环境

接口、分组、调试、流程均挂在**项目**维度下。

### 5.1 创建项目

「项目管理」→ 新建：填写项目名称（必填）、描述。创建后即可在其下维护环境与接口。

### 5.2 环境管理

一个项目可建多个环境（如 dev / test / prod），环境核心是 **Base URL** 与 **变量表**：

| 变量 | 来源 | 用法 |
|---|---|---|
| `baseUrl` | 环境配置的 Base URL | 调试/流程请求 URL 的前缀 |
| 自定义变量 | 环境变量表（key-value） | 任意位置 `{{变量名}}` 引用 |

**示例**：环境 `local` 的 Base URL 为 `http://127.0.0.1:8081`，接口 URL 填 `{{baseUrl}}/actuator/health`，实际请求即为该地址。切换环境即切换整套变量，无需改动接口定义。

## 6. 接口收集（同步）

前提：业务服务已引入 `api-manage-tools`（接入四步见 README「tools 接入」，核心是依赖坐标 + 暴露端点 + `-parameters` 编译参数），并确认 `GET {业务服务}/actuator/api-manage` 可访问。

操作：「接口管理」选择项目 →「同步」→ 填写业务服务的 manage 地址（如 `http://127.0.0.1:8080/actuator`）→ 执行。

同步采用 **diff 预览** 模式：

| 差异 | 处理 |
|---|---|
| 远端有、本地无 | 标记「新增」，确认后插入 |
| 两边都有 | 比对参数结构，标记「更新」 |
| 本地有、远端无 | 标记「下线」（url_status=OFFLINE），不删除 |

确认后按 Controller 维度生成分组（api_group）并落库接口（api_url）。同步历史可在「同步日志」中查看。

## 7. 接口管理与调试

### 7.1 接口管理

「接口管理」页左侧为 **分组树**（按 Controller 维度分组），右侧为接口列表：

- 支持 **手工新增** 接口（无需依赖同步，sourceType=手工）；
- 可编辑接口的请求方法、URL、参数结构、返回结构、标签、状态；
- 「接口文档」入口可维护并查看 Markdown 文档（同步接口自动生成初稿，AI 可辅助生成）；
- 搜索框支持按名称 / URL 模糊检索。

### 7.2 接口调试（调试台）

从接口列表点击「调试」进入，或直接在调试台手工填写：

1. **选择环境**：URL 中可使用 `{{baseUrl}}`、`{{自定义变量}}`；
2. **填写请求**：Method、URL、Headers、Query、Body（form-data / x-www-form-urlencoded / raw-JSON）；
3. **发送**：响应面板展示 `status / costMs / size / headers / body`；
4. **保存**：调试记录自动落库，可在「历史记录」中回看与重发。

**AI 辅助**（需已配置 AI）：

- **生成测试数据**：根据接口参数结构一键生成 Body 数据，填充后可手工调整；
- **分析响应**：将本次请求/响应交给 AI，辅助定位报错原因、解读返回结构。

## 8. 流程编排

流程 = 多个步骤按顺序串行执行，前序步骤的**出参提取**结果可供后续步骤引用，实现「接口 A 出参 → 接口 B 入参」。

### 8.1 创建流程

「流程编排」→ 新建流程：填写流程名称（必填）、描述、所属项目；添加步骤（按排序号执行）。

### 8.2 步骤配置

| 字段 | 说明 |
|---|---|
| stepName | 步骤名称（必填） |
| stepType | `HTTP` 接口调用 / `DELAY` 延时等待 |
| urlId / requestUrl | 可关联已有接口，或直接填写 URL（支持 `{{var}}`） |
| requestHeaders / requestQuery | 键值对，均支持 `{{var}}` |
| bodyType / requestBody | 请求体类型与内容，支持 `{{var}}` |
| extractRules | 出参提取：`[{"varName":"token","jsonPath":"$.data.token"}]` |
| assertions | 断言：`[{"type":"EQUALS","target":"$.code","expect":"0","desc":"业务码"}]` |
| onFailure | 本步失败策略：`TERMINATE` 终止流程 / `CONTINUE` 继续下一步 |
| delayMs | HTTP 步骤执行前延时（毫秒）；DELAY 步骤专用 |
| enabled | 是否启用该步骤 |

**断言类型**：`EQUALS`、`NOT_EQUALS`、`CONTAINS`、`NOT_CONTAINS`、`NOT_NULL`、`GT`、`LT`、`GTE`、`LTE`、`STATUS`（STATUS 的 expect 填期望 HTTP 状态码）。target 填响应体 JsonPath，如 `$.data.status`。

### 8.3 变量衔接示例

以「健康检查冒烟流程」为例：

| 步骤 | 请求 | 出参提取 | 断言 |
|---|---|---|---|
| 1. 探活 | `{{baseUrl}}/actuator/health` | `healthStatus = $.status` | STATUS = 200 |
| 2. 引用复检 | `{{baseUrl}}/api/auth/me`（Header 带 `X-Health: {{healthStatus}}`） | — | CONTAINS `$.code` = 0 |

运行时选择环境（如 local），`{{baseUrl}}` 取环境值，`{{healthStatus}}` 取步骤 1 提取值。

### 8.4 运行与结果

- 点击「运行」：选择环境、可选传入初始化变量（initVars）、选择模式：
  - **DEBUG**（调试模式）：任一步失败立即终止，适合编排阶段排查；
  - **NORMAL**（正常模式）：按各步骤 onFailure 决定是否继续。
- 运行详情页逐步展示：请求快照、响应、提取结果、断言结果、耗时；
- **单步重跑**：失败步骤可单独重跑，以该步之前的上下文快照为基础，无需整条重放；
- **导入 / 导出**：导出生成纯流程 JSON（注意：导入时需提供**纯流程 JSON 本身**，不能是导出接口带 `ApiResult` 包装的完整响应，详见 FAQ）。

### 8.5 AI 生成流程

「AI 助手 → 生成流程」：输入自然语言描述（如「先探活 health，再登录拿 token，然后查询用户信息」），AI 基于项目 API 清单与流程 Schema 生成可导入的流程 JSON，导入后微调即可。

## 9. AI 助手

### 9.1 前提：配置 AI

「系统设置 → AI 配置」填写：

| 配置项 | 说明 | 示例 |
|---|---|---|
| ai.base-url | OpenAI 兼容网关地址 | `https://api.deepseek.com` |
| ai.api-key | 网关 API Key | `sk-...` |
| ai.model | 模型名 | `deepseek-chat` |
| ai.temperature | 采样温度（可选） | `0.7` |

保存后立即生效（客户端缓存自动失效重建）。可用「连通性测试」按钮验证（成功返回 `pong` 与延迟毫秒数）。

### 9.2 场景一览

| 场景 | 入口 | 用途 |
|---|---|---|
| 自由对话 | AI 助手页 | 通用问答 |
| 分析响应 | 调试台 | 解读请求/响应、定位问题 |
| 生成测试数据 | 调试台 | 按参数结构生成 Body |
| 生成接口文档 | 接口文档页 | 按接口元数据生成 Markdown 文档 |
| 生成流程 | 流程编排 | 自然语言生成流程 JSON |

> 未配置 AI 时，各 AI 入口置灰或提示「AI 未配置」，核心功能（同步/调试/编排）不受影响。

## 10. 系统设置

- **AI 配置**：见 9.1；保存后 `GET /api/ai/status` 的 `configured` 立即为 true；
- **修改密码**：校验原密码，新密码 ≥ 6 位，BCrypt 落库；
- **敏感信息保护**：
  - 查询配置时 `ai.api-key` 脱敏回显（前 6 位 + `****` + 后 4 位）；
  - 保存配置时若 api-key 为脱敏值或空串则**跳过不覆盖**，不会把掩码写回数据库；
  - 登录密码不出现在配置回显中（固定 `******`），修改只能走改密接口。

## 11. 常见问题（FAQ）

**Q1：AI 状态里 configured=true 但 ready=false，是故障吗？**
不是。`ready` 为**懒加载语义**：保存配置后客户端缓存失效，`ready` 暂为 false，首次成功调用 AI（如连通性测试、对话）后自动变为 true。只要 `configured=true` 且连通性测试通过即可正常使用。

**Q2：流程导出的 JSON 再导入报「流程名称不能为空」？**
导入接口要求**纯流程 JSON**（即导出数据里 `data` 字段的内容）。如果直接把导出接口的完整响应（带 `{"code":0,"data":{...}}` 包装）作为导入内容会校验失败。导入前请取 `data` 部分作为导入体。

**Q3：流程运行报 Connection refused？**
多为环境的 `baseUrl` 指向了无服务端口。检查所选环境的 Base URL 是否可达（例如本机管理端在 8081、业务服务在 8080，环境需指向正确端口）。

**Q4：运行时传入的 initVars 和环境变量同名，谁生效？**
**环境变量优先**。流程引擎会先放入 initVars，再用所选环境变量覆盖同名 key。因此 `baseUrl` 以环境为准，initVars 适合传入 token、业务参数等环境里没有的变量。

**Q5：同步时报错连不上 manage 地址？**
确认三点：业务服务已引入 tools 依赖并暴露 `api-manage` 端点（`management.endpoints.web.exposure.include` 需含 `api-manage`）；地址填到 `/actuator` 级别；业务服务与编译参数 `-parameters` 正常（否则参数名丢失，接口元数据不完整）。

**Q6：同步后接口不见了 / 状态变了？**
远端已不存在的接口会被标记为「下线」（OFFLINE）而非删除，可在接口列表按状态筛选后手工处理。

**Q7：忘记 admin 密码？**
删除数据库 `sys_config` 中 `auth.password` 那条记录并重启应用，密码将重置为初始的 `admin123`（同时请尽快改密）。

**Q8：调试 form-data 请求有注意事项吗？**
管理端支持 form-data 编码发送；若目标服务对 multipart 边界有特殊要求导致异常，可改用 x-www-form-urlencoded 或 raw-JSON（form-data 跨网络场景未全量实测，见测试报告遗留事项）。
